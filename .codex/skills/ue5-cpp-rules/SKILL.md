# UE5 C++ 规则

## 概述

每次实现或修改 UE5 C++ 代码时，都遵循这些项目规则。优先采用现有代码风格和本地模式，而不是引入新的组织方式或暴露约定。

## 必需规则

1. 让新增接口专注于 C++。
   - 除非用户明确要求暴露给 Blueprint，否则不要添加面向 Blueprint 的函数接口，例如 `BlueprintCallable`、`BlueprintPure`、`BlueprintImplementableEvent` 或类似说明符。
   - 优先使用普通 C++ 方法；仅在周边代码已经需要时才使用 UE 反射。
   - 让用户单独创建 Blueprint 接口。

2. 对广播事件使用动态多播委托。
   - 实现事件式广播或观察者通知时，使用 UE 动态多播委托声明，例如 `DECLARE_DYNAMIC_MULTICAST_DELEGATE...`。
   - 不要对广播事件使用原生 C++ 多播委托，例如 `DECLARE_MULTICAST_DELEGATE...`、`TMulticastDelegate`，或普通 C++ 委托模式。
   - 除非用户明确要求，否则不要添加 `BlueprintAssignable` 等 Blueprint 暴露。

3. 按明确用途组织头文件声明块。
   - 先检查附近已有头文件，并遵循它们的块名称、顺序、访问区段、间距和注释风格。
   - 按职责对声明分组，不要混杂无关的函数和变量。
   - 常见声明块包括重写函数、仅服务器函数、外部查询接口、外部修改接口、可配置变量、私有辅助函数和运行时变量。
   - 将每个新增函数或变量放入与其用途匹配的声明块。

4. 为系统级变更更新文档。
   - 如果实现设计或修改了系统级行为、架构、玩法子系统、网络流程或其他跨模块约定，读取 `doc/` 下的相关文件。
   - 当代码变更改变已记录的行为时，在同一任务中新增或更新匹配的 `doc/` 文档。

5. 保证TS代码编译正确.
   - 如果实现或修改了 UE5 C++ 代码，确保相关的 TypeScript 代码编译正确。

## 完成前

回复前按这些规则复查变更。如果编译与任务相关，说明已按项目规则刻意不运行编译，因为该项目将编译留给用户。
